Three ideas carry everything




It is a container, components are the behaviour


A new GameObject does nothing. Add a MeshFilter and MeshRenderer and it is visible; add a Collider and things bump into it; add a Rigidbody and gravity takes it. Your own scripts are components too: every MonoBehaviour is one.


Transform · where it isMeshFilter + MeshRenderer · what it looks likeCapsuleCollider + Rigidbody · how it collidesPlayerController · what you wrote


This is composition: you build a Player by stacking parts, not by inheriting from a Player class.


Transform makes a tree


Every GameObject has exactly one Transform and it can never be removed. Transforms parent to each other, so the Hierarchy is a tree. A child stores its position relative to its parent (localPosition); its world position follows the parent.



Move, deactivate or destroy the parent and the children come along. In the editor above, drag Player and watch Sword.


Active vs enabled


SetActive(false) switches off the whole GameObject and everything under it. component.enabled = false switches off one component and leaves the rest running.

What Unity calls on your components, in order


These are MonoBehaviour messages. Unity calls them on every enabled script on an active GameObject.


    

  1. Awake()
    Once, as soon as the object is created or loaded and active, even if the script itself is disabled. Grab references with GetComponent here.
    2. 

  2. OnEnable()
    Each time the object or script becomes active. Subscribe to events here.
    3. 

  3. Start()
    Once, just before the first Update, only if the script is enabled. Safe to talk to other objects; all Awakes have run.
    4. 

  4. FixedUpdate()
    On the physics clock (0.02 s by default), possibly several times in one frame. Apply forces to Rigidbodies here.
    5. 

  5. Update()
    Every frame. Input, timers, most gameplay. Use Time.deltaTime for frame-rate independence.
    6. 

  6. LateUpdate()
    Every frame after all Updates. Cameras that follow a player belong here.
    7. 

  7. OnDisable()
    When the object or script is switched off, and before destruction. Unsubscribe from events here.
    8. 

  8. OnDestroy()
    When the object is destroyed or its scene unloads. Destroy() takes effect at the end of the current frame, not instantly.
    9. 



Read down, then across. The three blue calls repeat every frame until the object is disabled or destroyed.









The scripting API you will use every day


using UnityEngine;

public class Spawner : MonoBehaviour
{
    [SerializeField] GameObject enemyPrefab;  // drag a prefab in
    [SerializeField] Transform spawnPoint;

    Rigidbody body;                           // cache once

    void Awake()
    {
        body = GetComponent<Rigidbody>();
        if (!TryGetComponent(out AudioSource sfx))
            sfx = gameObject.AddComponent<AudioSource>();
    }

    public void Spawn()
    {
        // Clone a prefab: position, rotation, parent
        GameObject enemy = Instantiate(enemyPrefab,
            spawnPoint.position, Quaternion.identity, transform);
        enemy.name = "Enemy";
    }

    void OnTriggerEnter(Collider other)
    {
        if (other.CompareTag("Enemy"))        // no string garbage
            Destroy(other.gameObject);        // gone at end of frame
    }

    void Rearrange()
    {
        Transform sword = transform.Find("Sword");     // child by name
        sword.SetParent(null, worldPositionStays: true);
        foreach (Transform child in transform) { }     // walk children
        gameObject.SetActive(false);                   // children too

        // Unity 6.5: 64-bit EntityId replaces int GetInstanceID()
        EntityId id = gameObject.GetEntityId();
        Object same = Resources.EntityIdToObject(id);
    }
}






Getting hold of a GameObject


Best: a [SerializeField] field you drag a reference into in the Inspector. No searching, and it survives renames.


From a component: every component has .gameObject and .transform, so a collision or a GetComponent result leads straight to the object.


By search: GameObject.FindWithTag("Player") or FindAnyObjectByType<T>(). Fine in Start, too slow for every frame.


Prefabs


A prefab is a GameObject saved as an asset, components and children included. Instantiate clones it into the scene; InstantiateAsync does the same over several frames for big batches. Edit the prefab and every copy updates, unless that copy overrides the value.


Tags and layers


A tag is one label for code (CompareTag). A layer is for the engine: which cameras draw it, which physics layers collide, what raycasts hit.

Pitfalls that catch everyone once


    

  • GetComponent or Find in Update
    Each call searches. Cache the result in a field in Awake and reuse it.
    • 

  • transform.position.x = 5; won't compile
    Vector3 is a struct copy. Read it, change it, write it back: var p = transform.position; p.x = 5; transform.position = p;
    • 

  • Destroy(this) keeps the GameObject
    It removes only this script. Use Destroy(gameObject) to remove the object and its children.
    • 



    

  • Destroyed is not quite null
    Unity overrides == so a destroyed object equals null, but ?. and ?? skip that check. Write if (enemy != null) or if (enemy).
    • 

  • SetActive(false) stops coroutines
    Coroutines started on that object end and don't resume when it is reactivated.
    • 

  • Ids stored as int
    Since 6.5 an EntityId is 8 bytes. Saving it as an int, or parsing an old 32-bit string, throws away the version half and lookups fail.
    •
